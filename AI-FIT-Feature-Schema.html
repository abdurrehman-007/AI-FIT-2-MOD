AI-FIT Database Schema

Local setup uses SQLite and local sign-in. Firebase is inactive.

Collections

SQLite stores records in documents(collection TEXT, id TEXT, body TEXT NOT NULL). The primary key is (collection, id). The fields below are stored inside the JSON body. When Firestore is enabled, the same records are stored as collections and documents.

FeatureCollection / document keyFields and types
Accountsusers/{uid}id, email, name (string), store (store ID or null). Local accounts also have password (hash string) and optional password_version (string). Firebase Auth manages its own credentials.
Stores and settingsstores/{storeId}id, name, chart_status (string), owner (user ID or null for the demo), chart (legacy cm map), charts (category map in inches), baseline_orders, baseline_returns (integer).
Catalog and inventoryproducts/{productId}id, store, sku, name, category, color, image (string), price (number in PKR), stock (integer), sizes (string array), sample, active (boolean). image is an image ID or empty string.
Uploads and generated previewsimages/{imageId}id, kind (person, garment, or result), owner (user ID), created (Unix seconds). Image bytes live in the server's instance/images directory by default, including when metadata uses Firestore.
Try-on, sizing and retail analyticsevents/{eventId}id, kind, store (string), time (Unix seconds). Fields vary by event type, as shown below.
Local sign-in throttlinglimits/{uid}id (string), attempts (integer), until (Unix seconds).
Local reset-email throttlingreset_limits/{uid}minute (integer, Unix minutes).
QR and kioskUses the existing store and account recordsQR payload is generated from the store ID and configured public URL. No separate QR or kiosk collection.

Size chart fields

Path: stores/{storeId}.charts.{category}.{size}. Sizes are XS, S, M, L, XL and XXL. All chart values are numeric body measurements in inches.
